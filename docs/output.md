# 输出与格式

## 头部

前五行是固定信息，其中两行与计价有关：

```
Agent 用量统计
Agent     dsh（DeepSeek Harness (DSH)）
数据目录  /home/user/.dsh
时间范围  全部时间
计价来源  DeepSeek 官方（CNY → USD）
汇率      1 CNY = 0.149149 USD · 内置种子汇率 exchangerate-api.com · 2026-09-21
```

- **计价来源**写厂商和它这次用的那套价格表；发生折算时用 `→` 标出目标货币，直接使用厂商发布的表时不折算、不出现汇率行（中文环境用人民币表、英文环境用美元表）。
- **汇率**只在真的折算时出现：写明等式、来源、汇率日期。只给了 `--currency-rate` 而没给币种时，计价来源会写成"按 1 CNY = 0.5 折算，未指定目标货币"，金额不带货币符号。
- `--rate-mode historical` 时改为一行"按记录日期 · 来源与覆盖区间"，计价来源里写明"按每条记录当天的汇率折算为 X"。
- 价格表里的单价也在折算范围内，所以 `计价区间` 的 `P（$ / 百万 token）` 与金额同币种。
- **读到多个 agent 时**（默认的 `--agent all`），`Agent` 行列出全部 id（`claude·dsh`），`数据目录` 行按同样顺序列出各自的数据根，用 `, ` 分隔。

## 形态

文本报告是一棵树：**总 → 项目 → 会话**（`--subagent` / `--subagents` 再往下加范围层）。每个节点占两行——

```
Memolink (~/ws/apps/Memolink) 2026-08-16
  I/M 889K ¥2.8527 · I/C 257.6M / 99.7% ¥12.1085 · I/T 258.5M ¥14.9612 · O 368K ¥2.8015 · R 558K / 60.3% ¥4.2527 · O/T 926K ¥7.0542 · T 259.4M · Q 1,027 · ¥22.0154
  重启后继续lynx-rewrite开发 2026-09-06
    I/M 107K ¥0.1606 · I/C 18.4M / 99.4% ¥0.9207 · I/T 18.5M ¥1.0813 · O 44K ¥0.1995 · R 58K / 56.6% ¥0.2604 · O/T 102K ¥0.4599 · T 18.6M · Q 151 · ¥1.5412
```

名称行**只有名字、日期和子代理数**，数字全在下一行。这样标题多长都不会把整行撑开，也就不需要表格的固定列宽。

名称行还会带一个状态标记：被 agent 归档（在它自己的界面里被收起来）的会话写成 `名字（已归档）`。归档**不减少任何数字**——token 已经花掉了，标记只说明 agent 把它收在哪。

### 合并了多个 agent 时

一次运行读到多个 agent 时，每个层级都要说清数字是谁的：

```
agent-usages · 2026-09-17 · claude·codex·dsh · 12 会话 · 19 子代理
  claude  I/M 82K ¥0.0894 · I/C 106K / 56.3% ¥0.0032 · … · T 189K · Q 10 · ¥0.0981
   codex  I/M 97K ¥0.1067 · I/C 2.36M / 96.1% ¥0.0531 · … · T 2.48M · Q 109 · ¥0.2372
     dsh  I/M 1.62M ¥1.8766 · I/C 747.8M / 99.8% ¥16.4545 · … · T 751.5M · Q 2,261 · ¥27.6934
      总  I/M 1.80M ¥2.0727 · I/C 750.3M / 99.8% ¥16.5108 · … · T 754.2M · Q 2,380 · ¥28.0287
  修复 pnpm cli 用量数据查找（8 个子代理） 2026-09-25 · dsh
    I/M 1.62M ¥1.8765 · … · T 751.5M · Q 2,260 · ¥27.6928
```

- **项目行**多了三段：涉及哪些 agent（`claude·codex·dsh`，按 id 排序）、`N 会话`、`N 子代理`。
- **指标行按 agent 分列**：每个 agent 一行，agent id 右对齐成一列，最后一行是该项目自己的 `总`。指标行本来就有十项，横着再分列会没法读，所以是**按 agent 拆成多行**而不是加列。各 agent 行逐项相加正好等于 `总` 行（请求数、token、金额都精确相等）。
- **会话与子代理行**以 `· <agent>` 结尾，用来区分不同 agent 的会话（id 也可能重名）。
- 根部 `总` 块同样按 agent 分列；`session list` 的标题格也会带 `· <agent>`。
- **只读到一个 agent 时上述标记全部不出现**：单 agent 的报告保持原样，不会在每一行重复同一个 id。

按 agent 的完整数字也在 JSON 里：顶层 `agents[]`、每个项目的 `agents` / `agentTotals[]`。

同一个 git 仓库出现多个项目时，树里还会多一层**仓库行**（`Memolink 仓库 · 2 个项目`），仓库行的数字是下面各项目之和；只有它一个节点时连根节点那行都省掉。项目行上的徽标说明它跟仓库的关系——`· git worktree · lynx-rewrite`、`· git submodule · inner`、`· git repo · Memolink`（git 的术语不翻译）；主工作区不加徽标，因为仓库行就写着它。详见 [Git 工作区](README.md#git-工作区worktree)。

## 指标字段

每一项都带**它自己产生的费用**，所以可以只看输入，也可以只看输出，不必只看总额。

| 标签 | 含义 | 带金额 |
| --- | --- | --- |
| `I/M` | 未命中缓存的输入（input miss） | 是，独立计费项 |
| `I/C` | 缓存命中输入（cache read），后跟 `/ 缓存命中比` | 是，独立计费项 |
| `I/W` | 缓存写入输入（cache write），**仅在不为 0 时出现** | 是，独立计费项 |
| `I/T` | 输入合计 = `I/M + I/C + I/W` | 是，三项之和 |
| `O` | 输出（非思考） | 是，见下面的分摊 |
| `R` | 输出（思考，reasoning），后跟 `/ 思考占比`，**仅在不为 0 时出现** | 是，见下面的分摊 |
| `O/T` | 输出合计，即供应商报告的 completion 数 | 是，`O + R` |
| `T` | Token 总计 = `I/T + O/T` | 否（行尾的总额就是它） |
| `Q` | 请求数 | — |
| 行尾 | 该节点费用总额 | — |

两个比值都是**按 token 算的**，旁边的金额是**按价格算的**，两者不必同比例：

- **缓存命中比** = `I/C ÷ I/T`，例如 `99.7%`；
- **思考占比** = `R ÷ O/T`，例如 `60.3%`（思考是输出的一部分，所以分母是输出合计）。若思考集中的那段时间/模型单价更低，`R` 旁边的金额就会明显低于这个百分比。

四个桶**互不重叠**，所以 `I/T = I/M + I/C + I/W`。**思考 token 是输出的一部分**：`O/T = O + R`，供应商把它报在 completion 计数里，只计一次。

**`R` 可能是 0**：推理 token 由 provider 上报，新版 DSH 默认的 `messages` 协议不带这个字段（见 [DSH 适配器](agents/dsh.md)），此时思考计 0，`O` 与 `O/T` 仍是真实的 completion 数。工具不会去估算。

## 金额怎么分

- 计费项只有四个（`I/M`、`I/C`、`I/W`、输出），它们的钱**精确**；
- 输出按输出总量计价，所以 `O` 与 `R` 是**输出账单的拆分**，`O + R` 正好等于 `O/T`。拆分在**单价已知的那一层**做（模型 × 区间 × 峰谷），再逐段相加——如果按整棵树的 token 占比平均分，思考集中在高价时段时钱就会被摊薄到别处去；
- 行内恒等**精确成立**：`I/M + I/C + I/W = I/T`、`O + R = O/T`、`I/T + O/T = 行尾总额`；
- **每个会话只计价一次**（精确累加到「会话 × 模型 × 区间 × 峰谷」这一段，然后取整一次），上面所有层级都只是把这些已经算好的数字相加：项目 = 各会话之和，根 = 各项目之和，自身/子代理 = 各自的会话之和，模型行 = 各区间之和。所以**每一层都等于它下面所有行相加**，一个 0.0001 都不会差；token 数与请求数本来就精确相加。
- `I/T`、`O/T` 是各自组成部分之和，**不是第二笔账**，所以整行永远对得上：`I/T + O/T = 行尾总额`。

token 数字用紧凑写法（`K` / `M` / `B`，三位有效数字），显示值相加可能差最后一两位——底层是精确整数，只有这一处是显示近似。金额不做近似：它的每一位都精确相加。

## 折叠规则

同一个数字不在两处重复：

- 项目名下只有一个会话 → 不打印项目自己的指标行（项目名保留作分组标题）；
- 报告里只有一个项目 → 也不打印根部 `总` 的指标行；
- 会话没有子代理 → 不打印 `子代理` 行，`--subagent` 下也只留一行。

## 日期

- **窗口标题**：`标签 · 数据实际跨度`，按该窗口内第一条到最后一条请求算，因此半开的结束边界不会写成第二天。**同日才带小时**：`2026-07-01 8h~23h`；整段落在同一个小时里写成 `2026-07-01 8h ~`。同月只写一次月份（`2026-07-01 ~ 09`），跨月写全（`2026-07-01 ~ 2026-08-05`）。窗口内没有用量就不带跨度。
- **项目名后是开始日**，**会话与子代理名后是结束日**；与上一级显示的日期相同就省略，所以不会出现一列重复的日期。

## 时间窗口

默认只输出一段：**总**（全部时间）。`--range` 指定后输出那一段。

| 参数 | 范围 |
| --- | --- |
| （默认） | 全部时间 |
| `--range today` / `week` / `month` / `year` | 今日 / 本周（周一开始）/ 本月 / 今年 |
| `--range week-1`、`month-1`、`year-1`、`today-7` | 上一周 / 上个月 / 去年 / 7 天前（也认 今日/本周/本月/今年） |
| `--range A..B` | 任意区间，**左闭右开**：`2026-09-01..2026-09-19` 不含 19 号 |

端点可以只写一边（`..2026-09-19`、`2026-09-01..`），也可以只写一个时间（等于"从这时起"）。裸日期是本地 00:00；带时间必须写全 `YYYY-MM-DDTHH:MM:SS`，可带 `Z` 或 `±HH:MM`，不写时区就是本机本地时区。

## 范围拆分

| 参数 | 效果 |
| --- | --- |
| （默认） | 子代理并入其父会话，不单独占行 |
| `--subagent` | 每个项目、每个会话拆成 **总 / 自身 / 子代理** 三行 |
| `--subagents` | 在 `--subagent` 之外，把每个子代理也逐个列出 |

```
Memolink (~/ws/apps/Memolink) 2026-08-16
  总      I/M 889K ¥2.8527 · I/C 257.6M / 99.7% ¥12.1085 · … · Q 1,027 · ¥22.0154
  自身    I/M 680K ¥2.0000 · I/C 252.3M / 99.7% ¥11.9000 · … · Q 931 · ¥18.0882
  子代理  I/M 209K ¥0.9400 · I/C 5.27M / 96.2% ¥0.7912 · … · Q 96 · ¥3.9273
```

恒等式在每一层都成立：**自身 + 子代理 = 总**（有测试断言）。会话标题后面会标出它覆盖的子代理数。

## 多模型

一个会话可以跨多个模型（切换模型、子代理用别的模型）。**默认仍然只有一行**：金额是各模型各自计价后相加的结果，因为所有价格在进入内存前就统一换算到同一显示货币，所以永远可加。

要看清这一行是怎么拆的，加 `--models`：**每个节点**（项目、会话、子代理，只要它用了多个模型）会多出每个模型一行，这些行相加正好等于它上面那一行：

```
  创建回忆主题HTML风格展示集（5 个子代理）
    I/M 258K ¥1.0141 · I/C 8.93M / 97.2% ¥0.9741 · … · Q 153 · ¥4.452
    [deepseek-v4-pro]  I/M 209K ¥0.94 · I/C 5.27M / 96.2% ¥0.7912 · … · Q 96 · ¥3.9273
    [deepseek-v4-flash-vision-exp]  I/M 49K ¥0.0741 · I/C 3.66M / 98.7% ¥0.183 · … · Q 57 · ¥0.5248
```

只有一个模型的节点不会多印这一行。一个节点（会话）的行、它的模型行、它的计价区间，描述的都是**它整棵子树**（自身 + 它派生的子代理）；子代理自己作为一行时，描述的是那棵子树的子树。`--cost` 的计价区间里，每一段写明**请求当时用的模型名**。

## 默认之外的附加块

默认都不显示，按需打开：

| 参数 | 内容 |
| --- | --- |
| `--cost` | `计价区间`：每个 (模型 × 区间 × 峰谷) 一段，含指标行、金额与单价 |
| `--models` | 多模型节点逐个模型展开 |

`计价区间` 每段三行——标题（区间、峰谷、模型）、该段自己的指标行、以及单价：

```
计价区间:
▸ 2026-08-23 空闲时段 · deepseek-v4-flash-vision-exp · 价格模型 deepseek-flash
  V4-Flash（正式版）峰谷定价（周末全天低谷）（2026-08-23 00:00 → 2026-09-10 12:00 (UTC+08:00)）
  I/M 49K ¥0.0741 · I/C 3.66M / 98.7% ¥0.183 · I/T 3.71M ¥0.2571 · O 34K ¥0.1529 · R 26K / 42.9% ¥0.1148 · O/T 59K ¥0.2677 · T 3.77M · Q 57 · ¥0.5248
  P（¥ / 百万 token）: I/C 0.05 · I/M 1.5 · O/T 4.5
```

- 单价**按计费项给**，用与指标行同一套标签（`I/C`、`I/M`、`I/W`、`O/T`），单位是「显示货币 / 百万 token」；
- 一次用量横跨两档峰谷时就会出现两段，同一段时间在不同模型下也会有两段——标题里的模型名就是用来区分这种情形的；
- 模型名按**请求当时写的名字**分组：别名与正式名算两个模型，各自成段；
- 按默认模型计价、或按区间外最近一段价格计价时，标题下会标明原因。

## HTML 报告

`--html [路径]` 把同一份已经算好的报告写成一个**单文件 HTML**：样式与条形图内联，没有脚本、没有外链，可以直接双击打开，也可以当附件发出去或归档——换台机器、断网都不缺东西。

```bash
agent-usages usage --html /tmp/report.html            # 写到文件
agent-usages usage --range month --html ~/report.html # 可以配合其他选项
agent-usages usage --html - | head -c 200             # 写到 stdout
agent-usages usage --html > report.html               # 不带值也是 stdout
```

- 文件里是**同一个报告层算出的数字**：金额、token、请求数都取自文本报告用的那一份结果，格式化规则也一样（金额按需去尾、token 用 `K`/`M`/`B`），因此两种输出逐位相同；HTML 只做展示，不重新计价。
- 结构：头部（Agent、数据目录、时间范围、计价来源，发生折算时多一行汇率）→ 总计 → 每个项目一张卡片（项目自身的指标 + 会话表）→ 折叠的 `计价区间` 与 `提示`。
- 会话表与项目行的列是 **token 五桶**（`I/M`、`I/C`、`I/W`、`O`、`R`，与文本同一套标签）+ `T` + 请求数 + 金额，会话表末尾另有首次/最近日期。
- 每个项目的 token 总量画成一条**内联 SVG 横条**，宽度按本次报告里最大的项目归一化，谁占大头一眼可见；整张图只有 `<rect>`，不引入任何图表库。
- 所有文本都做 HTML 转义：标题里的 `<`、`&`、emoji 原样显示，不会破坏页面。
- 只有一个模型的节点不重复列模型行（与文本的折叠规则一致）；用了多个模型时以折叠的「各模型明细」给出。`--cost` / `--models` 在 HTML 里没有开关作用：计价区间总是以折叠块给出，多模型节点也总是能展开明细。
- `--subagent` / `--subagents` 下，会话行下面多出 `自身` / `子代理` 两行，`自身 + 子代理 = 总` 在表里同样成立。
- **不带路径（`--html`）或路径写成 `-`** 时文档直接写到标准输出，便于管道与重定向，此时不打印 `已写入` 提示、也不打印文本报告。
- 写了文件时只打印一行 `已写入 <路径>`，不再打印文本报告；同时给了 `--json` 时 JSON 仍写到标准输出，提示行改到标准错误，脚本的 stdout 保持可解析。
- `--html -` 与 `--json` 同时给出时 stdout 让给 JSON（脚本要的是可解析输出），HTML 跳过并在标准错误说明原因。
- 写不进去（目录不存在、没有权限）时报 `无法写入 <路径>: 原因` 并以退出码 1 结束；范围内没有用量时文件照写、退出码仍是 2。

## JSON

`--json` 与文本同源：顶层就是那一份扁平结构（库层面支持一次渲染多段，此时是 `sections: [{ label, … }]`）。项目与会话都带 `own` / `spawned` / `nodeTotal` 三段，金额仍是十进制字符串；`pricingBands` 里每一项都带 `model`、`models`、`periodId`、`tier`、`tokens`、`cost` 和 `components`（每项的 `rate`、`tokens`、`amount`）。字段清单见 [README](../README.md)。

与合并层有关的字段：顶层 `agents[]`（每个 agent 的会话数、子代理数、请求数、token、金额，`Σ = totals`）、`projects[].kind`（`repo` / `directory`）、`projects[].workspaces`（该项目覆盖的全部路径）、`projects[].agents` 与 `projects[].agentTotals[]`（`Σ = 该项目`）、`sessions[].agent` 与 `sessionReports[].agent`（会话来自哪个 agent，id 保持原样）。
