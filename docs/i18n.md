# 国际化

界面语言只有两种：**中文（zh）**、**英文（en）**。

## 怎么选

**用户配置 > 系统语言探测 > 内置默认（zh）**，没有 `--lang` 参数——语言是人的属性，不是某条命令的属性。

探测只取语言、不看地区（`zh-CN`/`zh-TW`/`zh-HK` 都是中文），非中文语言统一用英文目录，`C`/`POSIX`
视为"没有意见"而退回默认。环境变量优先于 `Intl`：`LANG=C` 时 `Intl` 会回 `en-US`，那是 ICU 的默认值，
不代表用户选择了英语。

语言在 `buildProgram()` 之前定下来：commander 在解析时就要渲染帮助文案，半个报告一种语言比不翻译更糟。

## 目录

```
src/i18n/
  zh.ts      ← 唯一真相：所有文案；也是 Messages 类型的来源
  en.ts      ← const en: Messages = {...}：漏一个键就编译不过
  index.ts   ← 语言选择、setLanguage/t()、languageOf
  errors.ts  ← 诊断码、UserError、renderDiagnostic
```

- 带参数的文案是**函数**（`subagents: (n) => …`），不是占位符模板：翻译可以自由调整语序、标点、单复数，
  调用点不用知道。目录里函数的**参数类型**就是 `UserError` 的参数类型，写错即编译错误。
- 测试钉住两件事：两份目录的键一一对应（含参数个数），以及每个字符串都非空。

## 诊断码

领域层不认识语言，也无法让 CLI 猜出失败原因，所以抛错处只说 **code + 参数**，句子在读取 `message`
时才渲染：

```ts
throw new UserError('timeUnrecognized', { value: '"2026-09-01T10:30"' });
// zh: 无法识别的时间: "2026-09-01T10:30"（支持 …）
// en: unrecognised time: "2026-09-01T10:30" (accepted: …)
```

`ConfigError` 继承它，`message` 是 `路径: 句子`。注意 `Error` 构造函数会把 `message` 装成实例自有属性——
那样会遮住 getter，所以 `UserError` 调用 `super()` 时不传参数。

**警告也走同一套**：`UsageResult.warnings` 是 `Warning[]`（即 `UserError`），文本层渲染句子，
`--json` 两个都给（`{ code, message }`），脚本按 `code` 分支而不用读文案。适配器同样只报码，
`UsageDataset.warnings` 因此是 `Warning[]`。

## 哪些不翻译

| 内容 | 原因 |
| --- | --- |
| 指标缩写 `I/M`、`I/C`、`I/T`、`O`、`R`、`O/T`、`T`、`Q` | 标识符；两种语言同一套符号 |
| JSON 键与枚举（`off-peak`、`exact`…） | 机器可读 |
| 货币代码、金额、日期 `YYYY-MM-DD` | 中性；`range.preset` 也是中性的，`range.label` 才是文案 |
| 输入别名 `--range 今日`、`update 价格表` | 用户能敲的写法，不是输出 |
| `config/pricing.json` 的 `label` / `note` / 组件名 | 厂商数据的引文：人民币表用中文、美元表用英文（英文站自己的措辞） |

## 加一门语言

1. 复制 `zh.ts` 为 `xx.ts`，逐条翻译，`export const xx: Messages = {...}`；
2. 在 `index.ts` 的 `Language`、`CATALOGUES`、`LANGUAGES` 里登记，`languageOf` 里给出语言前缀的映射；
3. 跑测试：目录键与参数一致性、跨语言 JSON 一致性会自动校验。
